# Задержки очереди UI и повторный синхронный вызов

31 октября 2026 года. Минимальный Go — 1.27.1, проверки — Go 1.27.2.

Исправление [снимка 0×0](GL_CAPTURE_REPAIR.md) проверяло корректность захвата.
Оно не подтверждало устранение задержек интерфейса. На этом этапе отдельно
воспроизведены и исправлены два дефекта настольного диспетчера Granio.
Приложения, зависимости GL и GLFW не менялись.

## Длительная пачка коротких callback

Ранее перед следующим проходом обработки окон и кадром выполнялось до 64
callback UI-очереди. Ограничения времени не было. В native-пробе 48 callback
по 2 мс заняли 115,1 мс, за которые анимация не получила ни одного промежуточного
обновления. Это воспроизведение задержки кадра при очереди из коротких операций,
а не доказательство длительной работы отдельного обработчика приложения.

Теперь пачка ограничена одновременно 64 операциями, бюджетом 2 мс и ближайшим
дедлайном кадра. После достижения границы цикл возвращается к оконным событиям
и кадрам. Порядок принятых callback сохраняется, они не отбрасываются.
Частота кадров, автоматический выбор монитора и пробуждение из простоя сохранены.

В Windows-пробе после исправления все 48 callback завершились, а между ними
произошло 7 обновлений анимации. Общее время пачки — 128,7 мс. Это улучшение
отзывчивости во время обработки, а не ускорение выполнения самой пачки.
В X11 и Wayland были получены по 6 промежуточных обновлений.

Исходный сбой: [queue-before-windows.log](ui-dispatch-validation/queue-before-windows.log).
Проверка исправления: [driver-after-windows.log](ui-dispatch-validation/driver-after-windows.log).

Бюджет проверяется между callback. Уже исполняющийся обработчик, который сам
занимает сотни миллисекунд, этим механизмом не прерывается.

## Ожидание UI-потоком собственной очереди

`runOnMainWithWait` выполнял callback немедленно на UI-потоке только до запуска
цикла. Во время работы синхронное повторное обращение из UI-callback ставило
внутреннюю функцию в очередь и ожидало её завершения. UI-поток при этом не мог
продолжить чтение очереди. Исходный native-тест завершился по timeout 6 секунд;
стек показывает ожидание канала в `runOnMainWithWait` на главном потоке:
[reentrant-before-windows.log](ui-dispatch-validation/reentrant-before-windows.log).

Синхронный вызов из самого UI-контекста теперь выполняется немедленно.
Синхронный вызов из worker по-прежнему ожидает завершения на UI-потоке.
Асинхронный вызов во время работы остаётся отложенным; тест проверяет порядок
`1, 2, 3`. Защита от поздних обращений после завершения цикла сохранена.
Рекомендация публичного `granio.Do[AndWait]` для работы из фоновых goroutine
остаётся прежней; исправление не требует переносить отрисовку на другой поток.

## Проверки

| Среда | Native-набор с race | Обновлений между 48 callback |
| --- | --- | --- |
| Windows, OpenGL 4.6, NVIDIA 616.92 | 10/10 | 7 |
| X11 / Xvfb, Mesa OpenGL 4.5 | 11/11 | 6 |
| X11 / Xvfb, Mesa GLES 2.0 | 10/10 | 6 |
| Wayland / Weston 10.0.1 headless, Mesa OpenGL 4.5 | 11/11 | 6 |
| Wayland / Weston 10.0.1 headless, Mesa GLES 2.0 | 10/10 | 6 |

В набор входят три новых сценария диспетчера, пробуждение native-цикла,
анимации 120–360 Гц и прежние проверки пикселей захвата: 0×0, скрытый первый
кадр, alpha и GL-состояние. Desktop GL на Linux также проверяет переключение
контекстов и независимость таблиц функций после неудачного глобального reload.
Linux использовал llvmpipe; GLES-контекст ограничен версией 2.0 и проверен по
реальному `GL_VERSION`.

Дополнительно прошли:

- Три новых native-теста Windows с обычными проверками потока, без
  `migrated_fynedo`: 3/3.
- Race-наборы `internal/async`, `internal/app`, `internal/animation`,
  `internal/painter/gl`, `driver/desktop` на Windows и Linux.
- Сборка GLFW-драйвера для WebAssembly; браузерный runtime не проверялся.

Команды, журналы и побайтовая сверка трёх изменённых исходных файлов:
[checks.json](ui-dispatch-validation/checks.json).
В журналах заменены локальные абсолютные пути. Linux использовал отдельные
vendor/workspace и собственный Weston без изменения настроек стенда.

Отдельный короткий EXE собран через опубликованный модуль с `GOWORK=off`
и без `replace`. Повторный синхронный вызов завершился, все 48 callback
выполнены, между ними получено 24 обновления анимации. После пачки проверены
захват 320×240 и зелёный пиксель содержимого:
[published-runtime.json](ui-dispatch-validation/published-runtime.json).
Это отдельный проверочный потребитель, без изменений пользовательских приложений.

## Границы результата

Проверки подтверждают устранение двух описанных библиотечных сценариев.
Пользовательское приложение в них не участвовало; устранение всех наблюдаемых
в нём подвисаний не подтверждено. Для такого вывода нужны его фактическая
версия зависимостей и воспроизводимое действие.

Короткие пробы не являются измерением p95/p99, гарантией времени GPU или
аппаратной приёмкой GNOME/KDE/Fly, Intel/AMD и macOS. Длительные
performance-проверки не выполнялись.
