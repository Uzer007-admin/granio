# Прозрачные окна через DXGI и DirectComposition

2 ноября 2026 года. Совместимые окна Windows с заранее подготовленной alpha
используют аппаратный OpenGL → D3D11 → DXGI → DirectComposition. Поддерживаются
Transparent, Mica, Mica Alt, Desktop Acrylic и System Blur. Отрисовка OpenGL
сохраняется; кадр не читается в память CPU и не выводится через WGL SwapBuffers.

## Выбор поверхности

`GRANIO_WGL_PRESENT=auto` или отсутствие переменной выбирает этот путь для
подготовленной alpha-поверхности. `dxgi` включает тот же выбор явно. Обычное
непрозрачное окно использует DXGI swap chain, связанную непосредственно с HWND.
`wgl` выбирает прежний вывод. `GRANIO_RENDERER=software` сохраняет приоритет
и использует непрозрачный программный fallback.

Требуются desktop OpenGL, `WGL_NV_DX_interop2`, framebuffer blit и совместимое
аппаратное устройство D3D11. DirectComposition предоставляется начиная
с Windows 8. Системные материалы через документированный
`DWMWA_SYSTEMBACKDROP_TYPE` требуют Windows 11 build 22621 или новее.
GLES сохраняет прежний путь вывода. Без interop аппаратный DXGI не заявляется.

Материал или `PrepareAlpha: true` задаётся через `desktop.ConfigureWindowVisuals`
до создания окна. Позднее можно переключать материалы и Opaque на том же HWND.
Окно без предварительного резервирования возвращает `desktop.ErrVisualNeedsRecreate`
при позднем запросе alpha. Новая ветка обозначается
`desktop.VisualBackendDirectComposition`.

## Alpha и первый кадр

GLFW создаёт HWND с `Win32NoRedirectionBitmap` до установки WGL pixel format:
Windows отклоняет попытку добавить этот флаг к готовому окну. Старый WGL
blur-behind для такой поверхности не включается. Рамка, заголовок и системные
кнопки сохраняются.

Composition swap chain использует два буфера RGBA8, FLIP_SEQUENTIAL и
PREMULTIPLIED alpha. OpenGL back buffer копируется внутри GPU с восстановлением
read/draw framebuffer, read buffer и scissor. RGB уже умножен на alpha;
полностью прозрачный пиксель равен нулю по всем каналам.

Начальная служебная текстура 1×1 не присоединяется к visual tree. Перед Show
готовится полный кадр фактического размера, затем выполняются Present и первый
Commit. После создания или resize DXGI-буферы становятся готовыми только после
`Present` с `S_OK`. Последующие кадры требуют только Present. Нулевой размер
и сворачивание окна сохраняют последний кадр.

## Fallback и восстановление

Недоступность DirectComposition обнаруживается до показа. Неизменяемый стиль
HWND требует повторного создания ещё скрытого окна с обычной redirection
surface. Оно получает непрозрачный DXGI либо WGL при отсутствии interop.
Глобальные GLFW hints сбрасываются после каждой попытки, включая отказ.

Контрастная тема, запрет прозрачности, RDP, отсутствие композиции или системного
материала дают непрозрачные пиксели и причину в VisualStatus. При смене политики
alpha-окно сохраняет DirectComposition и HWND, поэтому прозрачность можно
восстановить без пересоздания окна. VisualFallbackFail отражается состоянием Failed.

После ошибки вывода библиотека выполняет одну немедленную попытку пересоздать
DXGI и дерево DirectComposition. Если ошибка повторяется, WindowVisuals
публикует `NativeFailure` и код HRESULT. Следующая попытка возможна при
перерисовке после паузы в одну секунду. Состояние готовности восстанавливается
после успешного кадра. Win32 проверяет устройство DirectComposition после
запроса `WM_PAINT`. Для первого скрытого кадра применяется тот же порядок.

Запрос смены материала в свёрнутом окне остаётся в `Pending`. После
восстановления размера применяется последний принятый запрос.

## Короткая проверка

Windows 11 build 26300, RTX 4080 SUPER, драйвер 616.92, Go 1.27.2:

- Нативные проверки с `-race`: скрытый первый кадр, alpha 0/64/128/192/255,
  порядок RGBA, resize, minimize/restore, Opaque ↔ Transparent, нулевой размер,
  предел ресурса, сохранение GL state и освобождение ресурсов.
- Реальный конфликт DirectComposition target проверяет отказ и непрозрачный
  fallback. Подменённый ответ DEVICE_REMOVED проверяет реальные новые
  GPU-ресурсы, включая восстановление первого скрытого кадра. Настоящий сброс
  видеокарты не выполняется.
- Оптическая проверка двух собственных окон: ошибка alpha не более 1/255,
  Mica и Mica Alt различаются, Acrylic реагирует на фон. Контраст шахматного
  фона: стандартное отклонение 119 без размытия и 0,449 с Acrylic.
- Первый показ содержит материал и корректную alpha, без чёрного кадра.
  Системная анимация Show отключена только у тестового окна, чтобы её
  масштабирование не подменяло проверку первого подготовленного кадра.

Другие GPU и Windows 22621/22631 требуют самостоятельной аппаратной приёмки.
Linux-проверки с Mesa llvmpipe подтверждают регрессию библиотек, а не эффекты
реальных GNOME/KDE/Fly. Длительные проверки производительности не выполняются.
Исходники приложений не изменяются.

[Состав проверок и результаты](windows-desktop-stall-validation/dcomp-checks.json).

На Windows 11 26H2 build 26300.9974 с RTX 4080 SUPER и драйвером 621.14 штатная
подложка Desktop Acrylic могла сохранять прежнее размытие при полном перекрытии
фонового окна. Для Desktop Acrylic на build 26300 с DirectComposition
используется совместимый путь через `AccentPolicy` с отдельными светлым и тёмным
оттенками. Он отключается при смене материала и при непрозрачном fallback.

Microsoft рекомендует `DwmSetWindowAttribute` для системных материалов.
Этот путь применяется и при недоступности обхода, и при включённом либо
непрочитанном флаге энергосбережения `GetSystemPowerStatus`. Запрет
прозрачности, высокий контраст и RDP учитываются до установки материала.
[SetWindowCompositionAttribute](https://learn.microsoft.com/en-us/windows/win32/dwm/setwindowcompositionattribute), [SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status), [правила Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic).

На build 26300.9974 прошли 20 направленных переходов между Desktop Acrylic,
Mica, Mica Alt, Transparent и непрозрачным fallback на одном HWND. Проверки
включали alpha, первый полноразмерный кадр, resize и восстановление после ошибки
представления. Смена энергосбережения проверена подменой ответа Win32 в тесте.

Оптический тест Granio повторно выявил устаревший фон даже с `AccentPolicy`
при полном перекрытии фонового окна. DXGI принимал кадр источника (`S_OK`),
в interop-текстуре был новый цвет, но Acrylic показывал прежний. Повторная
подача того же кадра со стороны источника обновляла фон в светлой и тёмной
темах. `Present1` и DirectComposition у фонового окна не устранили пропуск.
Повторная подача использовалась только в диагностике, так как требует участия
фонового приложения. [IDXGISwapChain::Present](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-present).

Отдельная Win32-проба с
`DesktopAcrylicController` из Windows App SDK 1.8 отследила изменения фона,
но после переключения не показала разницу между Mica и Mica Alt. Проверка
видимого обновления фона остаётся обязательной независимо от результата
нативного вызова. [DesktopAcrylicController.SetTarget](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.composition.systembackdrops.desktopacryliccontroller.settarget?view=windows-app-sdk-1.8).

### Локализация пропуска кадров на 26300.9974

В светлой и тёмной темах межоперационная текстура и фактический буфер
DXGI уже содержали новый цвет до вызова `Present`. Для этой проверки
`FYNE_DWM_VALIDATE_BACKBUFFER=1` добавляет в оптический тест копирование двух
пикселей в staging-текстуру. Чтение CPU выполняется после первого снимка.

Одиночные обновления от отдельного D3D11-процесса доходили до `Transparent`
во всех 20 случаях. Отдельный процесс Granio WGL/DXGI также прошёл 20 из 20
в `Transparent` в каждой теме. В пробе с `HostBackdrop` и Gaussian blur неразмытая
полоса показывала 20 из 20 кадров, а размытая область рядом — 10 из 20.
Пропуски воспроизвелись при полном и частичном перекрытии. При полном
перекрытии такой же эффект показал переносимый Windows Terminal 1.24.12741.0
с профилем Acrylic.
Сравнение использовало только области собственных тестовых окон.

Единое дерево `Windows.UI.Composition` с кистью `HostBackdrop` и DXGI-кадром
осталось контрольным вариантом. Оно сохранило размытие шахматного фона,
однако пропустило одиночные обновления. Та же проблема возникла в пробе
`DesktopAcrylicController` на одной цели композиции с `MicaController`.

При смене материала Granio проверяет снятие прежнего `AccentPolicy` перед
установкой атрибута DWM. Ошибка очистки доступна через `VisualStatus` с
`VisualNativeFailure`. Непрозрачный fallback сначала представляет кадр с
непрозрачными пикселями, затем снимает оставшуюся подложку.

На RTX 4080 SUPER с драйвером 621.14 прошли нативные тесты с `-race`, включая
все 20 переходов в каждой теме, первый кадр, alpha при масштабе 1× и 1,25×,
изменение размера, восстановление и обе политики fallback при ошибке очистки.
Во время тёмной матрицы окно ответило на 94 контрольных сообщения без тайм-аутов.
Финальный оптический прогон Granio прошёл в светлой теме и повторил пропуск
в тёмной теме при корректном DXGI back buffer.

### Обновление Desktop Acrylic на 26300.9974

При полноразмерном перекрытии исходный `AccentPolicy` показал 10 из 20
одиночных изменений. В режиме `Transparent` дошли все 20. Повторная запись
того же оттенка и дополнительный `Present` переднего окна пропуск сохранили.
Снятие и восстановление `AccentPolicy` в одном проходе оконного цикла
обновило DWM-подложку со стороны самого окна Granio.

Драйвер выполняет эту операцию раз в 66 мс только для подготовленного,
видимого Desktop Acrylic с DirectComposition на версии 26300.9974.
Стандартный цикл GLFW просыпается к ближайшему обновлению и обрабатывает
оконные события. Переустановка материала выполняется без перерисовки canvas
и повторной отправки GPU-кадра. При скрытии, сворачивании, смене материала
и потере готовой поверхности обновления приостанавливаются. Ошибка
переустановки даёт `VisualNativeFailure` и непрозрачную поверхность по
политике запроса. Новый запрос позволяет повторно включить материал.
[SetWindowCompositionAttribute](https://learn.microsoft.com/en-us/windows/win32/dwm/setwindowcompositionattribute).

В нативных тестах с `-race` на Windows 11 26300.9974, RTX 4080 SUPER и
драйвере 621.14 источники в отдельных процессах отправляли ровно один кадр
на изменение полностью перекрытого окна.

| Источник | Светлая тема | Тёмная тема |
| --- | ---: | ---: |
| D3D11/DXGI | 20/20 | 20/20 |
| Granio WGL/DXGI | 20/20 | 20/20 |

Во всех четырёх сериях размытие сохранилось, а в 77 выборках неподвижной
подложки цвет наблюдаемой точки не менялся. Оптические тесты подтвердили
первый полноразмерный кадр и premultiplied alpha. В обеих темах прошли 20
направленных переходов между пятью режимами на одном HWND. Отдельные тесты
подтвердили обе политики fallback при ошибке обновления, смену режима
энергосбережения, resize, сворачивание и восстановление DXGI.

Для повторения оптических проверок предназначен
`TestNativeAcrylicWithIndependentSource` с `FYNE_TEST_WINDOW_VISUALS=1`,
`FYNE_DWM_CROSS_PROCESS=1`, `GRANIO_WGL_PRESENT=auto` и
`GRANIO_REQUIRE_DXGI=1`. Запустите его с `FYNE_THEME=light` и
`FYNE_THEME=dark` на интерактивном рабочем столе. По умолчанию источник
запускается в дочернем процессе с драйвером Granio. Переменная
`FYNE_DWM_NATIVE_SOURCE` позволяет передать отдельный D3D11-источник,
который использует тот же протокол команд теста.

Основание интерфейсов: [composition swap chain](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcomposition),
[DirectComposition](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-dcompositioncreatedevice),
[системные материалы DWM](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type).
