# Подвисание видео и рабочего стола при запуске OpenGL

31 октября 2026 года. Описанная здесь неисправность не считается устранённой.

## Что проверено

Исходный симптом — при открытии Granio-окна затормаживаются также видео,
рабочий стол и другие приложения. Успешный ответ очереди Granio за доли
миллисекунды не проверяет задержки представления кадров других процессов.
Системный режим перемещения `SC_MOVE` — отдельный сценарий; его пауза не
объясняет зависание рабочего стола при обычном запуске без перемещения.

В короткой минимальной пробе с GLFW без Granio и прикладных виджетов:

| Операция | Один измеренный запуск |
| --- | --- |
| `glfw.Init`, вариант без GL | 12,6 мс |
| Создание окна `GLFW_NO_API` | 3,5 мс |
| `glfw.Init`, вариант WGL | 8,9 мс |
| Создание окна с WGL/OpenGL | 645,4 мс |
| `Show` WGL-окна | 10,2 мс |

Среда — Windows 11 build 26300, NVIDIA RTX 4080 SUPER, драйвер 616.92.
GLFW — `5c267d637d9d`, GL — `83550b6a7fd2`.
Данные первого запуска: [noapi.jsonl](windows-desktop-stall-validation/noapi.jsonl),
[wgl.jsonl](windows-desktop-stall-validation/wgl.jsonl).
Повторная проба с `QueryPerformanceCounter`:
[noapi-qpc.jsonl](windows-desktop-stall-validation/noapi-qpc.jsonl),
[wgl-qpc.jsonl](windows-desktop-stall-validation/wgl-qpc.jsonl).
Её исходники: [wgl-startup-probe](../scripts/wgl-startup-probe/README.md).

Это локализует существенную часть времени запуска в ветке создания WGL,
которая присутствует и без Granio. Замер не устанавливает причину торможения
других процессов. Это одна короткая проба без статистической приёмки.

В свежем WGL-окне фактически получен swap interval 1. Интервалы 0 и 1
переключаются. Первый Go-таймер записал короткие вызовы `SwapBuffers` как 0.
Повторный замер через QPC дал 0,034–0,137 мс при исходном интервале 1,
0,035–0,052 мс при интервале 0 и 0,038–0,049 мс при явном интервале 1.
Создание WGL заняло 670 мс, обычного окна — 2,7 мс. Это время возврата API,
а не физического отображения. Утверждение о зависании внутри `SwapBuffers`
по этому набору не подтверждается. Значение по умолчанию описано в
[WGL_EXT_swap_control](https://registry.khronos.org/OpenGL/extensions/EXT/WGL_EXT_swap_control.txt).

Диспетчер Granio на Windows пока не задаёт swap interval явно. Само это
наблюдение не доказывает связь с общесистемным подвисанием. Настройки драйвера,
композитора и приложений в ходе этой проверки не изменялись.

## Необходимая системная трасса

Для разделения создания контекста, работы OpenGL ICD, задержек DWM,
планировщика и сторонних модулей подготовлен
[`record-windows-graphics.ps1`](../scripts/record-windows-graphics.ps1).
Он собирает 20 секунд GPU/CPU ETW и счётчики выбранного процесса. Приложение
запускает пользователь после начала записи. Скрипт не запускает и не закрывает
приложения, не меняет драйвер или его настройки, не отправляет данные в сеть.
Каждая запись использует уникальное имя WPR; остановка адресована только ему.
Существующий каталог результата не перезаписывается.

WPR не смог начать запись из имеющегося процесса: `0xc5585011`,
`Failed to enable the policy to profile system performance`. В его токене
отсутствует `SeSystemProfilePrivilege`. Это ограничение записи, а не результат
диагностики GPU. Полноценная GPU-трасса пока не получена.

Проверка команды без записи и повышения прав:

```powershell
.\scripts\record-windows-graphics.ps1 -ValidateOnly
```

Для записи откройте PowerShell от имени администратора и выполните:

```powershell
.\scripts\record-windows-graphics.ps1 -Seconds 20 -ProcessName 'granio-app'
```

После сообщения о начале записи запустите именно проблемную Granio-сборку.
Вместо `granio-app` передайте имя её EXE без `.exe` в `ProcessName`.
Фактические зависимости можно проверить `go version -m путь-к-программе.exe`:
имя файла само по себе не подтверждает использование Granio/OpenGL.
Во время проверки запуска не перемещайте и не закрывайте окно. Через 20 секунд
трасса будет сохранена в новый каталог `graphics-trace-*` в корне репозитория,
независимо от текущего каталога PowerShell.
Результаты: `graphics.etl`, `capture.json`, `process-samples.json` и журналы WPR.
Проверяйте `trace_saved: true` и `process_seen: true`; наличие одного каталога
не подтверждает запись и запуск нужного процесса.
Скрипт не повышает права самостоятельно. Если остановка WPR не удалась,
журнал содержит имя собственного сеанса для восстановления.
Имя также записывается в `capture.json` до начала записи. В таком случае из
PowerShell администратора остановите только этот экземпляр:

```powershell
wpr -stop путь-к-результату\graphics.etl -skipPdbGen -instancename имя-из-capture.json
```

WPR записывает системные и прикладные ETW-события, которые анализируются в WPA:
[документация Microsoft](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/windows-performance-recorder).
Успешная запись с правами администратора и аппаратная проверка устранения
общесистемного подвисания остаются открытыми. Длительных performance-прогонов
на этом этапе нет.
