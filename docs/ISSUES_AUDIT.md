# Открытые проблемы Fyne и apps

На 12 октября 2026 года в Fyne открыто 655 issues, в apps — 3. Полный реестр
находится в [INVENTORY.md](issue-audit/INVENTORY.md), исходные описания и метаданные —
в [open-issues.json](issue-audit/open-issues.json). Для собственного форка первые
приоритеты — поведение кэшей после простоя, корректность ввода и завершения работы,
отзывчивость больших коллекций, DPI и обработка изображений.

Снимок включает все страницы открытых issues обоих репозиториев; pull requests
исключены. Закрытая история не входит в реестр текущих проблем. Заголовки и
основные описания просмотрены по всему реестру. Для выбранных проблем разобраны
обсуждения и соответствующие участки исходников. Пункты ниже различают результаты
наших проверок, наблюдения по коду и сообщения авторов issues.

## Состояние upstream

У Fyne 115 issues имеют метку `bug`, 196 — `unverified`, 102 — `enhancement`.
Метки могут пересекаться. Для взаимоисключающей классификации в реестре выбран
первый подходящий статус: 115 bug, 196 unverified, 100 enhancement,
16 information-needed, 7 question, 2 meta и 219 прочих.

## Что исправлено в нашей базе

- Тестовые приложения используют явно выбранный английский язык. Добавлен
  `lang.SetLocale`: пустое значение восстанавливает системный выбор, явно выбранный
  язык сохраняется при загрузке переводов. Это также даёт API для запроса
  [#5333](https://github.com/fyne-io/fyne/issues/5333). Уже созданные подписи интерфейса
  приложение обновляет самостоятельно.
- Сравнение PNG учитывает эквивалентность прямых и предварительно умноженных
  на alpha цветов, проверяет геометрию и допускает ограниченные различия
  округления на amd64. Максимальная разница канала — 30 из 255, средняя
  разница — строго меньше 0,5 на байт; это существующие пределы проверки
  darwin/arm64. Сначала всегда выполняется точное сравнение нормализованных
  пикселей. Полный набор также проверен на GOAMD64=v1. Эталонные PNG не заменялись.
  По сути это та же категория различий,
  которую описывает [#3681](https://github.com/fyne-io/fyne/issues/3681).
- Наблюдение за настройками сохраняется при удалении и восстановлении файла,
  не реагирует на соседние файлы и обрабатывает ошибки fsnotify. Тесты закрывают
  наблюдателей, используют независимые имена файлов и ожидают событие вместо
  расчёта на жёсткий предел 100 мс.
- Тесты apps используют map с отдельными ID, проверяют фильтрацию по платформе
  и сравнивают дату как момент времени UTC. Исправления сохранены в
  [apps-tests.patch](../patches/apps-tests.patch); скрипт сборки применяет патч
  только при необходимости и прекращает работу при конфликте.
- GLFW-тесты Windows ожидают завершение resize. Полный desktop-набор проходит
  с настоящим оконным драйвером и `-race`; точное сравнение размеров сохранено.

Эти исправления проверяются на нашем наборе тестов. Они не означают устранения
всех причин жалоб на нестабильность из
[#5457](https://github.com/fyne-io/fyne/issues/5457),
[#4976](https://github.com/fyne-io/fyne/issues/4976) и
[#5847](https://github.com/fyne-io/fyne/issues/5847): в обсуждениях фигурируют
разные причины, включая сдвиг текста и состояние шрифтов.

## Приоритетные дефекты и проверки

### Кэши и восстановление компоновки

[#6509](https://github.com/fyne-io/fyne/issues/6509) описывает удаление только что
использованных объектов после долгого простоя. В нашей базе `setAlive` использует
`cachedNow`, обновляемый в `Clean`. После паузы срок жизни может быть рассчитан
от старого времени и сразу оказаться просроченным. Соответствующий путь имеется
в `internal/cache/base.go`.

В [обсуждении](https://github.com/fyne-io/fyne/issues/6509#issuecomment-5464066539)
отдельно разобрано восстановление renderer без вызова `Layout`. В
`internal/cache/widget.go` renderer действительно создаётся и помещается в кэш
без восстановления размера. Автор приводит смещение центрированного текста
после истечения кэша; maintainer предлагает сначала исправить восстановление
компоновки, затем вернуться к таймингам.

Приёмка для форка: тест с управляемыми часами, сохранение нового элемента после
паузы, восстановление размеров Label/List/Tree после удаления renderer и
benchmarks горячего пути. Вызов `time.Now` для каждого объекта должен оцениваться
по стоимости, поскольку текущая схема специально избегает такого вызова.

Рост памяти объединяет
[#5486](https://github.com/fyne-io/fyne/issues/5486),
[#4908](https://github.com/fyne-io/fyne/issues/4908),
[#3401](https://github.com/fyne-io/fyne/issues/3401),
[#3713](https://github.com/fyne-io/fyne/issues/3713) и
[#5770](https://github.com/fyne-io/fyne/issues/5770).
Для решения нужны пределы памяти и профили на длинных таблицах, смене шрифтов и
частом декодировании изображений. Замена структур кэша без этих измерений не даёт
критерия готовности.

### Ввод и завершение работы

В [#6486](https://github.com/fyne-io/fyne/issues/6486) описана потеря состояния
удерживаемого Ctrl/Shift после автоповтора. В нашем
`internal/driver/glfw/window_desktop.go` функция `desktopModifierCorrected`
трактует любую action, отличную от Press, как отпускание. Поэтому ветка Repeat
действительно очищает бит модификатора. Нужен регрессионный тест последовательности
Press → Repeat → Release и проверка сочетаний с кликом и прокруткой.

Сценарии завершения нескольких goroutines и общих привязок данных требуют
отдельных stress-тестов по
[#5748](https://github.com/fyne-io/fyne/issues/5748),
[#5814](https://github.com/fyne-io/fyne/issues/5814) и
[#4890](https://github.com/fyne-io/fyne/issues/4890).
Успешный штатный прогон race не воспроизводит автоматически сценарии из этих
сообщений.

Для Android и мобильного web связаны ввод и состояние клавиатуры:
[#5695](https://github.com/fyne-io/fyne/issues/5695),
[#6527](https://github.com/fyne-io/fyne/issues/6527),
[#6587](https://github.com/fyne-io/fyne/issues/6587),
[#5663](https://github.com/fyne-io/fyne/issues/5663),
[#5916](https://github.com/fyne-io/fyne/issues/5916) и
[#2777](https://github.com/fyne-io/fyne/issues/2777).
Нужны устройства и реальные IME: имитация клавиш на desktop не покрывает
автоповтор, композицию символов, закрытие клавиатуры и изменение высоты canvas.

### Отзывчивость и задержки

Наиболее повторяющиеся сценарии — длинный Entry/RichText, большие List/Table,
быстрый ввод мыши и фоновые окна:
[#5297](https://github.com/fyne-io/fyne/issues/5297),
[#3506](https://github.com/fyne-io/fyne/issues/3506),
[#4156](https://github.com/fyne-io/fyne/issues/4156),
[#4997](https://github.com/fyne-io/fyne/issues/4997),
[#2506](https://github.com/fyne-io/fyne/issues/2506),
[#6124](https://github.com/fyne-io/fyne/issues/6124) и
[#4058](https://github.com/fyne-io/fyne/issues/4058).

Для собственной базы полезен фиксированный benchmark-набор: длинные строки,
виртуализированные коллекции, мышь 1000 Гц, пустое приложение и скрытые окна.
Критерии — задержка события до кадра p95/p99, число allocations, пик памяти и
CPU в простое. Оптимизации пула
[#5568](https://github.com/fyne-io/fyne/issues/5568), итерации таблиц
[#3427](https://github.com/fyne-io/fyne/issues/3427), повторных Refresh
[#5856](https://github.com/fyne-io/fyne/issues/5856) и buffer reuse
[#6500](https://github.com/fyne-io/fyne/issues/6500) стоит оценивать на этом наборе.

В [#6579](https://github.com/fyne-io/fyne/issues/6579) автор сообщает о запуске
`defaults read -g AppleLocale` при новых theme scopes на macOS. В нашей базе
`lookupLangFont` вызывает `lang.SystemLocale`, а go-locale использует этот
CLI-fallback на Darwin. Измерения времени в issue принадлежат автору; для
подтверждения выигрыша нужен macOS-профиль. Кэш locale и выбор font face следует
отделить от изменений цветового scope.

### Масштабирование окна и графический backend

Жалобы на resize, второй монитор и возобновление после сна:
[#6596](https://github.com/fyne-io/fyne/issues/6596),
[#6303](https://github.com/fyne-io/fyne/issues/6303),
[#6373](https://github.com/fyne-io/fyne/issues/6373),
[#6198](https://github.com/fyne-io/fyne/issues/6198),
[#6147](https://github.com/fyne-io/fyne/issues/6147),
[#5323](https://github.com/fyne-io/fyne/issues/5323),
[#3630](https://github.com/fyne-io/fyne/issues/3630) и
[#6540](https://github.com/fyne-io/fyne/issues/6540).
Матрица приёмки должна включать X11/Wayland, Intel/AMD/NVIDIA, разные DPI,
подключение и отключение монитора, hide/show и sleep/resume. Unit-тест геометрии
не подтверждает работу конкретного видеодрайвера.

[#6483](https://github.com/fyne-io/fyne/issues/6483) и
[#5763](https://github.com/fyne-io/fyne/issues/5763) поднимают выбор GLES, desktop GL
и EGL. Для Windows ARM64 требуется отдельная проверка создания контекста:
архитектура CPU сама по себе не определяет доступный графический API.

### Шрифты темы SVG и доступность

[#6589](https://github.com/fyne-io/fyne/issues/6589),
[#4982](https://github.com/fyne-io/fyne/issues/4982),
[#6450](https://github.com/fyne-io/fyne/issues/6450),
[#6016](https://github.com/fyne-io/fyne/issues/6016),

fallback шрифтов, CJK и RTL. В приёмку входят добавление строк после ThemeOverride,
повторное использование ячеек, изменение размера и текста, ширина двойных символов
и смешанный RTL/LTR.

Ограничения SVG перечислены в
[#5949](https://github.com/fyne-io/fyne/issues/5949),
[#585](https://github.com/fyne-io/fyne/issues/585),

[#1950](https://github.com/fyne-io/fyne/issues/1950) и

Нужен корпус SVG с mask, use, symbol, CSS-классами, текстом и наследованием стилей,
сравниваемый с браузером или другим стандартным renderer.

У macOS Accessibility отдельно описаны
[#6491](https://github.com/fyne-io/fyne/issues/6491) и
[#6492](https://github.com/fyne-io/fyne/issues/6492).
Проверка должна обращаться к AX tree и screen reader, а не только к PNG.

### Обработка TIFF и версия зависимости

В [#6560](https://github.com/fyne-io/fyne/issues/6560) обсуждается
[GO-2026-5032](https://pkg.go.dev/vuln/GO-2026-5032): TIFF PackBits до
`golang.org/x/image v0.41.0` может расходовать несоразмерные ресурсы на специально
подготовленном изображении. В нашем go.mod используется v0.24.0.

Ответ upstream утверждает, что TIFF не включён в Fyne. Для текущей базы это
утверждение не подтверждается: `go list -deps` обоих приложений включает
`golang.org/x/image/tiff`. Импорт приходит через `github.com/go-text/render`
и `github.com/go-text/typesetting/font`. При импорте TIFF регистрирует decoder в
`image`, а Fyne использует общий `image.Decode` для изображений.
Это подтверждённая цепочка включения декодера; вредоносный файл для истощения
ресурсов не запускался.

Перед публичным выпуском следует выбрать совместимое исправление зависимости
или backport. Обновление до v0.41.0 требует решения о минимальной версии Go;
текущее требование фреймворка — Go 1.22, рабочее окружение использует Go 1.27.1.

## Порядок развития собственного форка

1. Зафиксировать регрессии кэшей после простоя, удержания модификаторов и
   shutdown/data binding отдельными минимальными тестами.
2. Установить benchmark-базу для latency, allocations, памяти и CPU в простое.
3. Проверить матрицу DPI и графических контекстов на реальном оборудовании.
4. Устранить проблемы тем, текста, SVG, accessibility и установки приложений
   по воспроизводимым случаям из реестра.

Обновление снимка и реестра:

```powershell
python -X utf8 scripts/fetch-github-issues.py
python -X utf8 scripts/generate-issue-inventory.py
```

Первая команда читает GitHub, вторая строит реестр из локального снимка.
Состояния issues и комментарии на GitHub не меняются. Выбранные обсуждения
сохранены отдельно в [discussions.json](issue-audit/discussions.json).
