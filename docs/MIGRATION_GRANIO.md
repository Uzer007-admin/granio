# Переход на Granio

Granio — самостоятельное развитие Fyne с сохранением исходной истории и лицензий.
Новый модуль ядра — `github.com/Uzer007-admin/granio/v2`, имя пакета — `granio`.
Сохранён номер основной версии API, чтобы явно обозначить исходный контракт v2.

## Импорты и типы

```go
import (
    "github.com/Uzer007-admin/granio/v2"
    "github.com/Uzer007-admin/granio/v2/app"
    "github.com/Uzer007-admin/granio/v2/widget"
)

func main() {
    a := app.New()
    w := a.NewWindow("Приложение Granio")
    var content granio.CanvasObject = widget.NewLabel("Здравствуйте")
    w.SetContent(content)
    w.ShowAndRun()
}
```

Для переноса исходников заменяются префикс `fyne.io/fyne/v2` и квалификатор
типов `fyne.` на новые значения. При постепенном переносе допустим явный алиас:

```go
import fyne "github.com/Uzer007-admin/granio/v2"
```

Типы исходного Fyne и Granio принадлежат разным Go-пакетам. Зависимые расширения
следует переводить вместе с приложением. Одного `replace` в модуле библиотеки
недостаточно: такие директивы не наследуются внешним приложением.

## Команды

| Назначение | Новый путь в ядре |
| --- | --- |
| Утилита сборки и упаковки | `cmd/granio` |
| Настройки | `cmd/granio_settings` |
| Галерея | `cmd/granio_gallery` |
| Сохранённая демонстрация | `cmd/granio_demo` |

Актуальная отдельная утилита развивается в `granio-tools`.
Формат `FyneApp.toml`, существующие ключи `FYNE_*` и платформенные протоколы
сохраняются для совместимости. Название проекта не меняет формат данных пользователя.

## Библиотеки

| Компонент | Путь собственного модуля |
| --- | --- |
| OpenGL/GLES | `github.com/Uzer007-admin/gl` |
| Окна GLFW 3.5 | `github.com/Uzer007-admin/glfw/v3.5/glfw` |
| Генератор | `github.com/Uzer007-admin/glow` |
| D-Bus | `github.com/Uzer007-admin/dbus/v5` |
| WebGL | `github.com/Uzer007-admin/granio-gl-js` |
| Браузерные окна | `github.com/Uzer007-admin/granio-glfw-js` |
| Системный трей | `github.com/Uzer007-admin/granio-systray` |
| Кодеки изображений | `github.com/Uzer007-admin/granio-image` |

Ядро и его графические библиотеки опубликованы с согласованными версиями:
[modules.json](../ecosystem/modules.json). Внешняя установка проверяется при
`GOWORK=off`, без локальных `replace`. Для разработки доступны `go.work`
и подмодули. Непубликованная часть экосистемы отмечена в [реестре](ECOSYSTEM.md).

У форков сохранены теги исходного проекта. Они могут содержать прежний путь
модуля, поэтому до собственных выпусков используйте точную версию из реестра
либо проверенный коммит. `@latest` не используется как ссылка на ветку Granio.
CLI при создании нового проекта закрепляет согласованную версию ядра.

## Новые возможности

`theme.ModernOptions{FollowSystem: true, FollowSystemPalette: true}` включает
полную доступную системную палитру. Это явный выбор приложения: палитра рабочего
стола имеет приоритет над встроенными светлыми и тёмными цветами. Явный акцент
приложения сохраняется; системная высокая контрастность имеет приоритет.
При исчезновении провайдера восстанавливается собственная палитра темы.

`SystemAppearance.DesktopTheme` сообщает название темы, стиль, описание шрифта
и тему значков, если портал их предоставляет. Описание шрифта является метаданными;
автоматическая загрузка произвольных файлов шрифта или стиля Qt не выполняется.
Отсутствующие настройки остаются недоступными, без придуманных системных значений.

`desktop.DisplayDriver.DisplayInfo()` возвращает фактический оконный backend.
`SessionType` — подсказка окружения; она не доказывает работу через XWayland.
На Linux `FYNE_PLATFORM=x11` и `FYNE_PLATFORM=wayland` выбирают backend явно;
автоматический выбор допускает переход к другому доступному backend.

`widget.NewDataGrid` строит представление по устойчивым идентификаторам строк.
Источник обеспечивает быстрый доступ к значениям в потоке интерфейса.
Сортировка, фильтрация и группировка строят проекцию в памяти; создание виджетов
остаётся ограничено видимой областью. Данные удалённых источников нужно загружать
асинхронно до обновления интерфейса.
